Bare-metal x86_64 · Rust · no_std

A microkernel that boots to ring 3 and proves it.

KELLER-OS boots as a PVH ELF straight into long mode, replaces the 8259 with a Local APIC and an IO-APIC, starts its application processors with INIT-SIPI-SIPI, and drops into an unprivileged task whose own CPU frame testifies that it runs at CPL 3. The harness around it is not the guest marking its own homework: a separate process reads the wire, the disk image and the framebuffer from outside.

What is actually in the kernel

Every line below is a module in src/ with a self-test that runs at boot and reports what it measured, including the hardware this machine does not have.

arch/lapic.rs
The Local APIC's timer is calibrated against the PIT, not against arithmetic. The reload the clock arithmetic predicts does not survive being measured on QEMU, so the kernel probes a ladder of reloads, confirms the winner, and re-arms from its own handler.
arch/ioapic.rs
Interrupts are routed through the IO-APIC with the 8259 masked behind it: 24 redirection entries written and read back, the timer delivered through the controller.
arch/smp.rs
Application processors are woken with INIT-SIPI-SIPI and handed their own GDT, TSS and IST stack. Each one hashes a fixed workload and must agree on 5fa184c8…78ec — a hash no AP can fake by running a different code path.
paging.rs · idt.rs
Per-process PML4s mean two tasks can use identical virtual addresses and reach different frames, so a cross-space read is a not-present page fault rather than a check the kernel has to remember to make. int 0x80 is the only DPL-3 gate in the table.
crypto.rs · zk.rs
RFC 8439 ChaCha20-Poly1305, HMAC/HKDF, Reed-Solomon, Shamir 2-of-3 sharing and Schnorr proofs, all implemented in-tree with known-answer tests instead of a dependency tree.
storage.rs · ahci.rs
A real SATA disk carries the sealed vault, and the image is opened only after a proof has been checked against both the owner commitment and the header on the medium. A host-side reader then confirms independently that no plaintext is on the platter.
nic.rs · eth.rs
An Intel 82540EM with DMA descriptor rings puts sealed 576-byte frames on the segment as Ethernet/IPv4/UDP datagrams, answers ARP for its own address, and is validated frame by frame by a separate process acting as its peer.
gui/
A 1024×768×32 framebuffer display server with 8 window slots, dirty-rectangle blits on a fixed 100 ms refresh, click-to-focus routed through the window's capability, and a 256-line console ring that you can scroll with PageUp, PageDown or the mouse wheel.

Verification, not adjectives

The harness boots the kernel under QEMU, drives the shell over COM1, injects real keyboard and pointer input through the emulated 8042, and then checks the guest's account of every event it injected. Numbers below are from runs on this machine.

Measured on QEMU 11 with -cpu max, 4 cores where noted.
Check Result What it means
Full self-test suite 161 passed / 0 failed 20 further checks report themselves skipped: they need hardware this machine does not have.
Input probe 23 passed / 0 failed Real bytes through the 8042, and click-to-focus proved by a focus holder changing capability.
SMP, 4 cores 15 passed / 0 failed Three APs online; the pinned ChaCha20 digest matches on every core.
Wire and disk independent 11 frames validated from the peer's side of the cable; the vault image read back by a host tool.
Ring-3 containment 0 frames leaked A faulting CPL-3 task is retired, its address space torn down, the kernel keeps running.

The honest edge of that table: the NIC in this QEMU model exposes no MSI capability, so six MSI checks skip and the device keeps its IO-APIC line; the AHCI adapter checks skip entirely until a disk is attached; and a faulted task is retired rather than respawned.

Quickstart

Nightly Rust with rust-src, and QEMU on PATH. The kernel boots as an ELF through QEMU's -kernel loader, which is the path that works here: QEMU's multiboot ROM refuses ELF64 images.

  1. Build and boot it.
    bash 
    git clone https://github.com/KELLERBABG/KELLER-OS.git
cd KELLER-OS
cargo build --offline -Zjson-target-spec
qemu-system-x86_64 -cpu max -m 256M \
  -kernel target/x86_64-sovereign_core/debug/sovereign-core \
  -serial stdio -display none
  2. Or let the wrapper do it, including a windowed run with the emulated VGA adapter, a headless run for captures, and a machine with no display adapter at all:
    powershell 
    .\run.ps1                # window + COM1 on this terminal
.\run.ps1 -Headless      # adapter emulated, no window
.\run.ps1 -NoGraphics    # serial console only
  3. Watch it prove itself. Type selftest in the guest shell for the summary line above, gui test for the framebuffer probe, input test for the PS/2 probe, and disk test when a disk is attached.
    powershell — the scripted harness from dev-tools/ 
    python dev-tools\qemu_check.py --vga std --secs 110 `
    --stdin-script target\full-input.txt --stdin-delay 18 `
    --expect "SELF-TEST SUMMARY: 161 passed, 0 failed" `
    --forbid "LOCKDOWN"
